Key Concepts

Seven ideas that make the rest of HTTP easier to understand.

1. HTTP (HyperText Transfer Protocol)
The agreed set of rules browsers and servers use to exchange web content. It defines how messages are formatted and sent. See How HTTP Works.
2. The client-server model
The client (your browser) starts the conversation by asking for data. The server stores the data and answers. In our analogy: customer and kitchen. Learn more.
3. Requests and responses
Every exchange is a request followed by a response. Each message has a start line, headers and an optional body. Learn more.
4. HTTP methods
The verb in a request: GET reads, POST creates, PUT replaces, DELETE removes, and the new QUERY searches with a body. Two vocabulary words matter: safe (changes nothing) and idempotent (repeating has the same effect). Learn more.
5. Status codes
A three-digit number that reports the outcome. The first digit gives the family: 2xx success, 3xx redirect, 4xx client error, 5xx server error. Learn more.
6. Statelessness and cookies
HTTP forgets every request as soon as it is answered. Cookies stored by the browser and sent back with each request let sites remember logins and carts. Learn more.
7. HTTPS, TLS and encryption
HTTPS wraps HTTP in TLS so data is encrypted, tamper-proof and sent to a verified server. Plain HTTP sends everything as readable text. Learn more.
Also worth knowing: QUIC, the UDP-based transport behind HTTP/3, is covered on the Evolution page.
