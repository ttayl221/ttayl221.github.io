How HTTP Works

HTTP is the universal set of communication rules used by web browsers and servers. It dictates how messages are formatted and sent across the internet, and it powers every website visit, video stream and app data exchange.

The client-server model

1. The client (web browser)

  • Your device: laptop, phone or tablet.
  • Runs apps such as Chrome, Safari or a mobile app.
  • Starts the conversation by requesting data.
  • Renders the code it receives into a visual website.

2. The server (web host)

  • A remote computer in a data center running 24/7.
  • Stores site files, databases and media.
  • Listens for incoming client requests.
  • Processes each request and returns the data.

A restaurant is an easy way to remember who does what.

Life cycle of a web page visit

  1. URL entry. The user types a web address into the browser.
  2. DNS lookup. The browser converts the domain name into an IP address.
  3. HTTP request. The browser sends the "order ticket" to the server.
  4. Server work. The server fetches files and prepares the data.
  5. Rendering. The browser draws the HTML and CSS on screen.

Anatomy of an HTTP request

A request has up to three parts: a request line, headers and an optional body.

GET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
Accept: text/html
  • Request line: the HTTP method (action), the target path (resource) and the protocol version.
  • Request headers: metadata about the client, its language preferences and the content formats it accepts.
  • Request body (optional): data sent to the server, such as a form submission or JSON like {"username": "student123"}.

Anatomy of an HTTP response

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 3482

<html><body><h1>Welcome!</h1></body></html>
  • Status line: protocol version, numeric status code and a short reason phrase.
  • Response headers: content format, file size, caching rules and cookie instructions.
  • Response body: the payload itself: an HTML document, a JPEG photo or API data.
