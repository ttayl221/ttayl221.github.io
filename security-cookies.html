Security & Cookies

HTTP is stateless

  • Each HTTP transaction is completely independent.
  • By default the server does not remember who you are between requests.
  • This keeps servers from being overloaded, but it would break logins and shopping carts.

The solution: cookies

A cookie is a small piece of text the server sends in a Set-Cookie header. The browser stores it and attaches it to future requests, like a loyalty card at a diner.

HTTP/1.1 200 OK
Set-Cookie: session_id=abc123; Secure; HttpOnly

GET /account HTTP/1.1
Cookie: session_id=abc123

Is plain HTTP safe?

No. Unencrypted HTTP has three big weaknesses:

  • Plaintext transmission: data travels as readable text over port 80.
  • Eavesdropping and packet sniffing: anyone on public Wi-Fi can capture passwords, searches or messages.
  • Man-in-the-middle (MITM) attacks: an attacker can change a page or inject malicious code before it reaches you.

HTTPS and TLS/SSL

HTTPS is HTTP running inside a TLS/SSL secure connection, normally over port 443. Think of it as a locked delivery box.

  • Encryption: turns data into unreadable ciphertext while it travels.
  • Data integrity: shows that files were not tampered with.
  • Authentication: digital certificates verify that the server is genuine.
