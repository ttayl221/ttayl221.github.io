Methods & Status Codes

Every request names an action (the method) and every response reports an outcome (the status code).

HTTP methods

GET: fetch data

  • Retrieves or reads data from a server.
  • Safe and idempotent: does not change server state.
  • Parameters are added to the URL.
  • Can be cached and bookmarked.

POST: send or create data

  • Submits new data to be processed.
  • Changes state: creates new records.
  • Data travels in the request body, not the URL.
  • Not safe to resend automatically without asking the user.

PUT: update or replace

  • Replaces an existing resource completely.
  • Idempotent: repeating it gives the same result.
  • Example: editing a profile or a document.

DELETE: remove

  • Asks the server to remove a resource.
  • Idempotent: once it is gone, repeating the call has the same outcome.
  • Example: removing a photo, comment or account.

Safe means the request does not change anything on the server. Idempotent means sending it many times has the same effect as sending it once.

The new QUERY method (RFC 10008)

In June 2026 the IETF published RFC 10008, which defines the QUERY method. It is the first new standard HTTP method since PATCH in 2010.

  • The problem: GET cannot carry a body and URLs have length limits, while POST carries a body but implies the server's state may change, so it cannot be safely cached or retried.
  • The solution: QUERY combines GET's meaning (safe, idempotent, cacheable) with POST's ability to carry a body such as JSON.
  • Use cases: complex database searches, AI / RAG vector queries, GraphQL queries and large multi-parameter filters.
QUERY /products HTTP/1.1
Host: example.com
Content-Type: application/json

{"category": "laptops", "maxPrice": 900, "inStock": true}
Note: Headlines call this the first new method "in 20 years" or "in 16 years" depending on which method they count from. Either way, it is rare.

Status code families

Table 4. The five status code families
RangeNameMeaning
1xxInformationalRequest received; the process is continuing.
2xxSuccessThe action was received, understood and accepted.
3xxRedirectionFurther action is needed; the resource has moved.
4xxClient errorThe request has bad syntax or the item is missing.
5xxServer errorThe server failed to fulfil a valid request.
