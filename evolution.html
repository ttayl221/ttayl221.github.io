Evolution of HTTP

HTTP has been revised several times to make the web faster and more reliable.

From HTTP/0.9 to HTTP/1.1

HTTP/0.9 (1991)

Designed by Tim Berners-Lee. Simple GET requests for raw HTML text; the connection closed right after.

HTTP/1.0 (1996)

Added headers, status codes and media (MIME) types so the web could carry graphics and rich files.

HTTP/1.1 (1997)

Introduced keep-alive persistent TCP connections to cut network delay and server overhead.

HTTP/2 (2015)

  • Binary framing layer: replaced plain text with binary streams.
  • Multiplexing: sends many requests at once over a single TCP connection.
  • Header compression (HPACK) and a server push feature.

The head-of-line blocking problem

HTTP/2 still runs on TCP, which delivers packets in strict order. If one packet is lost on weak Wi-Fi, all streams stop and wait for the resend, like a traffic jam behind one stalled car.

HTTP/3 and QUIC

HTTP/3 replaces TCP with QUIC, which runs over UDP.

  • Independent streams: a lost packet in one stream does not stall the others.
  • TLS 1.3 required: security is built in, and unencrypted HTTP/3 does not exist.
  • 0-RTT handshakes: reconnecting needs no extra round trip, saving roughly 100–300 ms.
  • Connection migration: connection IDs let a download continue when you switch from Wi-Fi to cellular.

Why HTTP/3 matters on mobile

  • Faster page loads when the signal is weak.
  • Video and audio keep buffering without freezing.
  • Apps that make dozens of short API calls refresh faster.
  • Adoption is growing: one 2026 analysis (reference 7) reports that over 30% of top websites, including Google, Meta, Cloudflare and Netflix, use it.
